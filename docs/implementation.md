# Implementation notes

## Requirements versus prototype decisions

The established product is a native, shortcut-invoked visual navigator for real open windows and individual Chrome/Safari tabs, with immediate typing, meaningful Decisions refinement, and exact activation. Semantic output is bounded judgment, never a navigation destination.

The following are reversible prototype choices: Swift Package Manager rather than an Xcode project; a full-screen AppKit NSPanel with SwiftUI previews; Control–Option–M; a four-second native inventory refresh with workspace launch/termination/activation/Space notifications plus pushed browser inventory changes; 20-second cached local previews refreshed while visible; 180 ms debounce for uncached remote queries with immediate exact-evidence cache reuse; a proportionate window canvas with a horizontal browser strip at rest; one compacted canvas of plausible windows and tabs during search; independent predicate relevance; 96 candidates per request; in-memory 100-entry semantic cache.

The initial visibility/default-selection boundary is 0.4, a provisional UI heuristic rather than a calibrated probability threshold. Local exact matches are protected. Hidden items remain in the inventory and every candidate still receives semantic evaluation, so Decisions can recover matches missed locally. Explicit identity selection persists only while the target remains visible. Removal clears selection without silently choosing a different destination. Clearing the query restores the entire inventory.

## Mission Control interaction

The panel fills the current display over a dimmed local wallpaper image. Window previews retain their aspect ratios with small app/title badges. `ExposureLayout` maximizes preview area in centered rows, caps tab cards at 300 points wide, and lays out whatever order it is given; large inventories scroll rather than shrink below the minimum row height. Native capture also preserves aspect ratio. Geometry is display-only and does not enter semantic evidence or invalidate cached judgments.

The open and close zoom is Moonshine's own: Mission Control's animation lives inside the Dock process with no public API, and invoking it would show Apple's overview rather than this one. `WindowInventory` records a `ScreenFrame` for each window it matched to an on-screen CoreGraphics window; each tile keeps its final `ExposureLayout` size. `WindowZoom` maps the image within that fixed tile to its real screen rectangle (converted through the panel and canvas origins), and `AppModel.spread` animates a uniform scale and offset inside one spring. The text, clipping, and shadows no longer resize their layout each frame. Missing previews and offscreen windows fade at their grid positions. During exposure, inventory changes coalesce to the latest snapshot and preview capture pauses; finishing the transition publishes that snapshot and resumes previews. Typing ends the opening transition immediately so filtering never waits for the zoom. The panel is non-opaque and its backdrop fades faster than the tiles move, so the desktop is briefly visible beneath. Other applications' real windows cannot be hidden, which is why a tile covers its window only when a cached preview exists. Dismissal reverses the spring, returns focus immediately, and orders the panel out about 0.3 s later; a generation counter cancels that if the overview is reopened. Background self-test presentation and handoffs that already hid the panel skip the animation. Previews are captured eight at a time at up to 960 points wide so they can stand in for the window at full size.

At rest, native windows fill the canvas and every browser tab is reachable in a horizontal strip. View all tabs expands tabs into the canvas. Typing searches the complete inventory and replaces these areas with one canvas containing only plausible windows and tabs. Browser previews use title/domain/context metadata, never fabricated page images. The one-line footer displays the selected title/location, counts, and a spinner during refinement; status text appears only as a caveat (synthetic workspace, Decisions unavailable). Query-to-semantic timing stays in the Settings diagnostics.

Order and ranking: `WindowInventory` sorts windows front to back by correlating Accessibility frames with on-screen CoreGraphics bounds (ordering only, like previews; never activation). `SearchState` adopts that order while nothing is typed or explicitly selected and holds it still afterwards. With no query the default selection is the first window that is not in front. During search, results are ranked by `LocalMatch` tier with ties in inventory order, and candidates admitted only by Decisions follow in inventory order, so predicate probabilities are still not a ranking and late answers do not reshuffle local matches. `LocalMatch` adds title-prefix, word-start, app-prefix, initials, and one-edit typo tiers (two edits from nine letters; words under five letters stay exact).

`OverviewNavigation` models grid arrows, horizontal-strip movement, return to a remembered window, and forward/reverse cycling. Arrow navigation is constrained to visible results, with no hidden-item fallback for an empty result set. Search scores are computed once per state change and reused by layout/navigation. Query, refinement, refresh, and keyboard navigation reset pointer-selection eligibility, preventing a stationary pointer from taking over during reflow. Reflow uses a short animation unless Reduce Motion is enabled; distant selection reveal is immediate.

Standard AppKit application and Edit menus supply query editing and Quit commands. The search field stays first responder during result navigation. The visual iteration preserved adapters and input scope. The subsequent page-context extension adds optional evidence fields; activation targets and process-lifetime guards remain unchanged. Moonshine never performs a web search or opens a new URL; dispatch resolves an already-open local identity.

## Ownership and boundaries

- `MoonshineCore` owns immutable evidence, local matching, query/version checks, selection identity, Decisions request/response validation, cache, and aggregate metrics.
- `MoonshinePlatform` owns native discovery/activation, Chrome automation, local preview capture, and the paired browser bridge.
- `Moonshine` owns the menu, global shortcut, nonactivating panel, input focus, cards, settings, and asynchronous orchestration.
- `moonshine-check` provides opt-in count-only discovery, live synthetic smoke checks, and labeled quality evaluation.

Spleen and Moonshine remain separate applications and separate result views. Tab or Shift–Tab transfers the exact query through a local, versioned `spleen-search://search` or `moonshine-search://search` URL delivered to the companion's verified application bundle. The only other payload is the original foreground PID for Escape restoration. No destination or activation command is transferred. The receiver opens its own search and places the caret at the end. Queries are bounded and routes/fields validated; no clipboard or query file is used. Existing semantic settings apply in the receiving app. Spleen search entry does not trigger compass assessment-on-open.

The sender hides before transferring focus, retains the current search until Launch Services accepts, and restores it on failure. A closed companion is first launched in the background, then receives the search URL with explicit foreground activation. Spleen remembers its last normal data directory and lets a transferred search adopt the first completed index when its initial corpus is empty; subsequent updates keep the usual stable-result behavior. Handoff generations protect a newer incoming search from an older launch callback. A handoff that already hid the overview skips Moonshine's closing zoom. Repeated Tab events and marked-text composition do not trigger a switch; management forms retain native Tab behavior. The apps retain their own global shortcuts, credentials, and inventories.

## Identity and navigation

Native window identity retains the exact AXUIElement and a kernel process-start timestamp, with a UUID assigned for that element’s observed lifetime. Activation checks that the process is the same instance and that the retained element still appears in its window list. It unminimizes, activates the app, raises that element, then checks the focused window. Duplicate titles never drive dispatch. Unsupported targets fail visibly.

ScreenCaptureKit thumbnail matching uses PID, title, and geometry only when exactly one window matches. That correlation is exclusively for previews. The application never activates based on that match. Cached previews stay local and are identified in hover/accessibility help; background browser tabs are metadata-only.

Chrome Automation targets process lifetime plus numeric tab ID, and re-finds that ID across current regular windows at dispatch. Window/tab indexes are not persisted as targets. Profile names are not supplied by Chrome’s scripting dictionary. The extension provides separately paired profile identities. When any Chrome bridge client is connected, the prototype uses bridge inventory rather than mixing it with the automation inventory; connect all desired Chrome profiles or use Automation without the Chrome extension to avoid missing unpaired profiles.

Safari’s installed scripting dictionary exposes tab indexes, title/URL and a WebContent PID, but no supported stable tab ID or dependable private-window scope. Therefore a Safari scripting fallback was rejected. The shared WebExtension uses browser tab IDs, browser-session identity, per-profile client identity, and explicit private-status checks.

Browser activation also requires a macOS foreground handoff. `BrowserApplication` retains the running process and its start time before the exact-tab bridge command. After acknowledgement, the overview releases its key panel, Launch Services reactivates the existing browser bundle, and the adapter verifies the returned PID, process lifetime, and foreground application before completing. A failed handoff restores the same search. This is necessary because a background Safari extension can acknowledge tab selection without activating Safari, and direct `NSRunningApplication.activate` requests from the nonactivating panel can be refused. No URL is opened or used to resolve a tab.

A signed native messaging extension would give a stronger packaging/lifecycle story. The prototype instead uses an authenticated, loopback-only bridge so it can be tested without a developer signing identity. Permanent end-user Safari distribution still requires signed extension packaging and broader lifecycle/profile testing.

## Latency and transport

The version-2 browser protocol retains the existing authenticated `POST /sync` route and its bounded payload, origin, and loopback checks. A request advertises `transportVersion: 2`. After ingesting inventory and acknowledgements, the bridge holds an empty response for at most one second; queuing an activation wakes that client's matching-session request immediately. Version-2 replies contain `{commands, transportVersion: 2}`. Legacy clients receive the original command array without waiting, and updated clients still accept that array from older apps.

The extension keeps only one sync in flight. Successful version-2 syncs reconnect immediately, so no one-second scheduling gap separates commands from acknowledgements. Busy events coalesce into the next snapshot instead of being dropped. Acknowledgements survive delivery failure; completed command IDs suppress repeated browser actions. Offline attempts back off one second. Page-label collection stays independent of this path. Inventory sampling still happens approximately once per second while idle.

Changed bridge inventory emits a bounded `AsyncStream` notification. The app merges it with its last native/fallback snapshot without waiting for Accessibility discovery or native previews. A completed native scan re-reads current bridge inventory before merging so it cannot overwrite a newer browser event. The original twelve-second client freshness bound, 4.5-second command expiry, five-second activation timeout, and session/profile/tab identities remain. A new browser session now fails outstanding old-session commands immediately.

Semantic request construction and exact-evidence cache lookup run on `SemanticEngine`'s actor. A complete validated cache hit can apply without the typing debounce; a miss retains the 180 ms delay and all existing ticket/selection checks. Live Decisions requests share an ephemeral URLSession with cookies and response caching disabled. Cancelling one request does not invalidate the entire connection pool. The model, prompt, candidate coverage, and privacy scope are unchanged.

Monotonic timers measure local filtering, bridge command wait/acknowledgement, native handoff, total activation, and inventory application. URLSession task metrics separately expose connection/TLS duration and request-to-first-byte wait; the latter includes network and server work rather than isolating inference. Normal diagnostics remain bounded and in memory. `--inspect` additionally writes durations to stderr, with no queries, titles, URLs, IDs, or credentials. See `verification.md` for reproducible checks and validation limits.

## Boundaries still to prove

- Native Accessibility targets exist on the tested Mac, but some apps do not expose usable/focusable windows. Generic internal application tabs are not supported.
- Other-Space, full-screen, minimized, and app-specific activation behavior must be checked with representative real targets. No private CoreGraphics window-activation API is used.
- To avoid accidental private-browser capture, browser parent windows are excluded from generic window discovery. Browser content is represented by explicit non-private tab adapters. The browser exclusion list covers the common installed browser families; newly introduced browser bundles require review.
- Previews are cached stills and may be unavailable for offscreen/minimized/protected windows. Background tabs have no screenshot. This is not continuous live capture.
- Full-screen layout and filtering were visually checked with 31 synthetic windows/64 tabs and roughly 70 real destinations. Geometry tests cover up to 300 items. Smaller displays and larger real inventories still need acceptance testing. This is a Mission Control-inspired navigator, not a replacement for macOS Spaces management or live window compositing.
- Optional browser page context adds descriptions, headings, and control labels from enabled sites. It does not read full page/document bodies or keep activity history. Native windows still use title/app evidence; queries about unseen contents or “what I was debugging” remain unsupported.
- Rate limits, network failure, refusals, and invalid responses leave local search working. No automatic retry storm or app-wide network wait occurs.

## Page-context extension

`PageContext` bounds page labels, binds them to the exact current URL, and expires them after 120 seconds. Capture timestamps and full source URLs never enter remote input; unchanged text keeps the same cache key. The bridge accepts the optional field while remaining compatible with older extensions. `SearchState` defaults to title/URL evidence; its separate opt-in invalidates pending tickets and controls both local and remote use. Changed candidate evidence invalidates only that candidate's cached judgment; stale batches still fail the full ticket check. When only labels within the same URL/title/app change, a prior match can remain provisional for up to three seconds until a new answer arrives; completion, failure, expiry, revocation, or navigation removes provisional judgments. Refresh checks enforce the deadline. This prevents background control-label changes from immediately clearing an explicit selection.

The extension asks for `scripting` and the exact site's host permission only after Enable for this site. A separate local allowlist prevents an older broad Safari website grant from opting sites into collection. The collector reads HTML metadata and visible heading/button labels, including bounded same-origin embedded views. It avoids forms/editable descendants, numeric-only headings, other origins, private/unknown tabs, and discarded tabs. Full-URL checks before/after collection reject navigation races. Capture runs independently of one-second bridge sync, at most four captures per job, with per-page timeouts and a twenty-second refresh interval. Permission removal and the local opt-out clear caches; a background pending-intent handler finishes approved grants even when Chrome closes the popup during its permission dialog.

The request builder includes labeled `page_context` fields as untrusted data, with prompt version `moonshine-relevance-2-page-context`. Requests split recursively to respect both the 96-candidate and 128 KB bounds. This is evidence enrichment, not an LLM-generated description pipeline. The inspector shows the actual supplied labels.

Implementation references: [Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), and [Safari extension permissions](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions). Safari's updated collector still needs on-device acceptance; Chrome has been exercised with an explicitly enabled site.

## Prepared search and responsive opening

The November 13 latency pass prepares normalized titles, applications, URLs, page labels, token characters, and initials once per changed candidate. Each query is normalized once; semantic batches reuse its local scores. Source evidence retains its full local revision digest, and time-sensitive page context is still validated when making or applying a ticket. Geometry-only changes refresh displayed items without recomputing their text matches. SHA-256 output retains the same hexadecimal format with a cheaper encoder.

The overview keeps its scroll views alive across presentations and resets their position explicitly instead of rebuilding the entire tile tree. Handoff recipients prepare the transferred query before first layout; Spleen skips the intermediate compass layout. A shortcut can interrupt Moonshine's close animation immediately. Opening diagnostics separate model preparation and synchronous layout from overall dispatch; receiving handoffs record time until the editor accepts the caret.

Native discovery batches window attributes and yields between targets. Activation validates the retained identity as before, checking focused-window confirmation immediately and polling only if it is still pending. Preview work has its own cancellable task and generation, independent of discovery. Cached images retain their NSImage wrappers; offscreen and minimized windows do not trigger new capture enumeration, and unsuccessful visible captures retry at most every 20 seconds. Cancellation or a closed presentation prevents an old preview task from publishing images into a newer session. Failed fresh capture can keep an explicitly cached local preview until that target disappears or capture permission is unavailable.
